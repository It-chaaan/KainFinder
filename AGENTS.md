# Crave It project guidance

Crave It helps people discover food around a chosen search center in Metro Manila. The React frontend renders a Google Map, runs browser-side Places (New) Text Search on submit, and links pins, cards, locally calculated straight-line distances, and Google Maps directions. Browser location and manual city or map-point selection are implemented. The user confirmed live desktop search on localhost with a Maps Demo Key; an earlier dedicated narrow browser check verified live search, city-center changes, linked cards/pins, and the skip link. The new distance labels and legal links, real-phone behavior, and deployment remain unverified in a browser. Laravel still exposes `GET /api/health` only. Read `README.md` for setup and `docs/design.md` for UI direction.

- `frontend/` owns the React, TypeScript, Vite, and Tailwind interface. `backend/` owns the Laravel JSON API and database access. Root `compose.yaml` configures local frontend, API, and PostgreSQL containers; copy the example environment files before using it.
- Run `npm --prefix frontend run lint` and `npm --prefix frontend run build` for frontend changes. With Compose running, use `docker compose exec api php artisan test` for backend changes and `docker compose config` for Compose changes. Report checks blocked by an unavailable Docker engine rather than claiming they passed.
- Keep PostgreSQL access in Laravel; the current public-search flow runs in React with the Maps JavaScript API and browser-side `Place.searchByText`. Laravel remains for future application-owned data. A browser Maps key is visible, so restrict a production key by website and API; keep database credentials and other secrets out of source control. A Maps Demo Key is for local prototyping, not production. Check Google's terms before storing any Google place content. A city sets the search center, not a strict city boundary, and dish results do not confirm menus.
- Privacy and terms pages are public drafts with required owner/contact placeholders. Complete and review them before launch. Keep Google's map controls and attribution visible, and do not cache Google place content.
- Make focused changes, preserve existing work, and verify the affected part of the app. Do not describe planned product behavior as implemented.
